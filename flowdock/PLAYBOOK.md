# FlowDock 의존성 플레이북

> API 조합으로 **최대의 성능**을 내고, 사람들이 **끊지 못하게** 만드는 실전 설계.
> 모든 루프는 이 저장소의 실제 커넥터 13종으로 **지금 바로 실행 가능**하며 `templates/`에 탑재되어 있다.

원칙 한 줄: **의존 = 데이터 축적 × 습관 빈도 × 전환 비용.** 기능이 아니라 루프를 판다.

---

## 1. 의존 루프 포트폴리오 (템플릿 갤러리 탑재)

`flowdock templates use <name>` 으로 설치. 온보딩 퍼널 순서대로:

| # | 루프 | 템플릿 | 빈도 | 축적되는 것 | 크리덴셜 |
|---|---|---|---|---|---|
| 1 | **여명 브리핑** — 아침 오디오 브리핑 + 긴급속보만 따로 | `dawn-briefing` | 매일 | 튜닝된 소스·습관 자체 | **0개 (완전 키리스)** |
| 2 | **밤의 기억 은행** — 저녁 회고를 벡터 일기로 영구 적재 | `night-memory-bank` | 매일 | `diary` 컬렉션 (하루 1알) | embed·Qdrant (로컬화 가능) |
| 3 | **세컨드 브레인 인입** — 공유한 URL을 요약·태깅해 기억으로 | `second-brain-ingest` | 공유마다 | `memory` 컬렉션 (수백 개/분기) | embed·Qdrant |
| 4 | **기억 소환** — "내가 뭐 읽었지?" 출처 붙은 RAG 답변 | `second-brain-recall` | 질문마다 | Q&A까지 재저장 → 자기 진화 | embed·Qdrant |
| 5 | **여론 파수꾼** — 4시간마다 감시, 새 전개만 알림 | `reputation-sentinel` | 24/7 | 평판 연대기 + 판정 이력 | embed·Qdrant |
| 6 | **콘텐츠 증폭기** — URL 1개 → 스레드+커버+오디오 초안 | `content-amplifier` | 발행마다 | 스타일 프롬프트·산출 이력 | Discord webhook |

### 온보딩 퍼널 (무료 → 의존 → 구독)

```
여명 브리핑 (키리스, 5분 설치)          ← 첫 접촉: 크리덴셜 0개로 내일 아침 바로 가치
   ↓ 매일 아침 울리는 습관
밤의 기억 은행 / 세컨드 브레인 인입+소환   ← 코어 락인: 벡터 기억이 매일 쌓이기 시작
   ↓ 3개월 뒤: 수백 개의 검색 가능한 '내 기억'
여론 파수꾼 (24/7)                      ← 끌 수 없는 의존: 끄면 놓친다
   ↓ 실행 이력 = 감사 추적 = 디버깅 데이터
Free 7일 로그 보존의 벽 + 월 100회 실행 한도   →   Pro/Team 전환
```

**전환 논리**: 파수꾼·소환 루프는 실행 이력이 곧 사용 가치(판정 로그·답변 근거)다. Free의 7일 보존·100회/월 한도에 부딪히는 순간이 곧 "이미 의존하고 있음"의 증거이며, 그때 업그레이드는 선택이 아니라 복구다.

### 왜 이 조합이 못 떠나게 만드나

- **벡터 기억은 이전 불가**: 임베딩 공간은 모델·컬렉션에 묶인다. 3개월치 `memory`/`diary`/`chronicle`을 다른 도구로 옮기면 전부 재크롤링·재요약·재임베딩해야 한다.
- **루프가 서로를 강화**: 인입(3)이 쌓은 기억을 소환(4)이 꺼내 쓰고, 문답이 다시 기억이 된다. 파수꾼(5)은 자기 연대기를 dedup 필터로 재사용한다 — *데이터가 기능을 개선하는 플라이휠*.
- **습관 이중화**: 아침(1)·저녁(2)이 하루를 여닫고, 공유(3)·질문(4)이 낮을 채우고, 파수꾼(5)이 밤을 지킨다. 하루 중 FlowDock이 없는 시간이 없다.

## 2. 성능 극대화 플레이북 (무료 티어를 끝까지 짜내기)

실전에서 검증된 규칙들 — 전부 템플릿에 이미 반영되어 있다:

1. **원문이 아니라 '요약 카드'를 임베딩하라.** 8k 토큰 한도 초과를 원천 차단하고 임베딩 지연·비용을 수십 배 줄인다. (`second-brain-ingest`의 enrich→embed 순서)
2. **자연키를 upsert id로 써서 중복 저장을 없애라.** URL·헤드라인이 id면 재공유·재탐지가 덮어쓰기가 된다 — 벡터 수 = 고유 지식 수. 커넥터가 문자열 키를 결정적 UUID로 변환해 Qdrant 제약도 통과시킨다.
3. **`if` 가드로 쿼터를 지켜라.** 빈 추출 → 체인 전체 캐스케이드 스킵(쓰레기 저장·헛 임베딩 방지), LLM 판정 `false` → 알림 억제(중복 푸시 = 신뢰 잃는 지름길 + 쿼터 낭비). *조용함이 기능이다.*
4. **LLM에게 'false 한 단어' 프로토콜을 시켜라.** 판정 노드의 출력이 곧 다음 노드의 `if` 입력이 되게 — 별도 분기 커넥터 없이 표현식 truthiness로 흐름 제어. (`isTruthy('false') === false`)
5. **임베딩·벡터를 로컬화하면 전 루프가 무과금이 된다.** `EMBED_BASE_URL`을 Ollama/llama.cpp의 OpenAI 호환 엔드포인트로, Qdrant는 셀프호스트(기본 `localhost:6333`) — 키리스 스택 완성.
6. **레이트리밋은 엔진에 맡겨라.** 커넥터별 토큰버킷이 초과 요청을 실패 대신 큐잉한다. llm.chat 1req/1.5s는 노드당 1콜 설계로 충분; 버스트 인입은 embed 5/s·vector 10/s가 흡수.
7. **재시도는 외부 I/O 노드에만.** `retry: {max:3, backoffMs:800~2000}`은 jina/LLM 같은 플레이키 소스에만 — 멱등한 upsert는 실패 시 재개(resume)가 더 싸다.
8. **알림엔 본문+오디오 링크를 함께.** tts.speak는 URL 생성만 하므로 비용 0 — 같은 브리핑을 텍스트·오디오 두 채널로 소비하게 해 습관 접점을 늘린다.

### 커넥터별 무료 한도 예산 (현재 레이트리밋 설정)

| 커넥터 | 버킷 | 하루 이론치 | 병목이 되는 루프 |
|---|---|---|---|
| llm.chat | 1 / 1.5s | ~57k | 없음 (노드당 1콜) |
| jina.reader | 5 / 1s | 432k | 없음 |
| embed | 5 / 1s | 432k | 없음 (카드 임베딩 시) |
| vector.* | 10 / 1s | 864k | 없음 |
| ntfy | 2 / 1s | 172k | 없음 |

→ 실질 병목은 레이트리밋이 아니라 **플랜의 월 실행 한도**(Free 100회). 파수꾼(하루 6회)+아침·저녁(2회)만으로 월 ~240회 = **Free를 자연스럽게 초과** → 설계된 전환 압력.

## 3. 다음 천장을 올릴 능력 (→ M4로 전부 출하됨 ✅)

의존 루프를 설계하며 드러났던 3가지 — 전부 구현되어 엔진에 들어갔다:

1. ✅ **kv.get / kv.set 상태 노드** — 정확한 이전-상태 비교. `page-change-watcher` 템플릿이 벡터 우회 없이 kv 스냅샷으로 실질 변화를 판정한다.
2. ✅ **독립 노드 병렬 실행** — 레벨 단위 동시 실행 + 세마포어. 동시성 상한이 **플랜의 maxConcurrency**(Free 2/Pro 8/Team 20)라서 성능 자체가 과금 레버가 됐다. 실패한 노드의 같은-레벨 형제는 체크포인트를 남기고, 다음 레벨만 중단(재개 시 이어서).
3. ✅ **응답 캐시** — `ctx.fetch`에 GET TTL 캐시(`serve --cache-ttl`). egress 샌드박스 검사 **이후**에 캐시를 조회하므로 캐시가 샌드박스를 우회할 수 없다.

남은 로드맵: map/fan-out 노드(동적 DAG), 프로세스 수준 커넥터 격리, Cloudflare Workers 배포.
